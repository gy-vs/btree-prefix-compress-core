# 页式 B-tree 叶页前缀压缩

本项目把叶页键统一视为二进制字节序列，叶页启用前缀压缩和重启点；内部页继续保存完整分隔键。

## 构建与测试

```sh
npm install
npm run build
npm test
```

## 页头

所有整数均为小端序。固定页头长度为 20 字节：

| 偏移 | 长度 | 字段 |
| --- | ---: | --- |
| 0 | 2 | magic，固定为 `0x4650` |
| 2 | 1 | 版本，当前为 `1` |
| 3 | 1 | 页类型/标志：`0` 叶页，`1` 内部页 |
| 4 | 4 | payload 字节长度 |
| 8 | 4 | 叶页记录数，或内部页分隔键数 |
| 12 | 2 | 叶页重启间隔；内部页为 `0` |
| 14 | 2 | 叶页重启点数量；内部页或空叶页为 `0` |
| 16 | 4 | CRC-32C 校验值 |

CRC 覆盖整页除 16..19 外的所有字节；计算时把校验字段视为零。读取页时先确认页总长度和 CRC，再信任 payload、偏移、数量和长度字段。

## 叶页 payload

叶页布局：

```text
header | encoded entries | restart-offset[u32] * restart_count
```

每条记录编码为：

```text
shared_prefix_len : u32
suffix_len        : u32
value_len         : u32
suffix_bytes      : suffix_len
value_bytes       : value_len
```

完整逻辑键由以下方式重建：

```text
previous_logical_key[0 .. shared_prefix_len) ++ suffix_bytes
```

编码采用规范形式：`shared_prefix_len` 必须是与前一条逻辑键的最长公共前缀长度；重启点处必须为零。键按无符号字节序严格递增，空键是合法键。

## 重启点与查找

默认重启间隔为 **16 条记录**，实现允许 1..65535。每 16 条记录的第一条保存完整键（`shared_prefix_len = 0`）。重启点表保存相对 payload 的 `u32` 偏移，必须严格递增，且第一个偏移必须为零。

查找流程：

1. 校验 CRC 和结构性边界；
2. 只解码每个重启点上的完整键；
3. 二分重启点，找到最后一个 `<= target` 的重启键；
4. 在该区间内最多顺序重建 15 条前缀压缩键；
5. 使用重建后的完整逻辑键比较。

间隔越小，点查需要顺序解码的记录越少，但完整键和重启表开销越大。16 适合常见的 4 KiB..64 KiB 页；设为 1 可完全关闭前缀压缩。

## 内部页

内部页暂不压缩，格式为：

```text
first_child:u32
( key_len:u32, key_bytes, child:u32 )*
```

序列化长度为 `20 + 4 + sum(8 + key_len)`。子指针数量始终比分隔键多一个。叶页分裂上提的是右侧第一条完整逻辑键，因此分裂不会丢掉公共前缀。

## 基于编码大小的重写、分裂和合并

插入、更新和删除都可能改变相邻键的最长公共前缀，因此受影响叶页必须重新编码。

分裂和合并只以编码后字节数为准，不以记录数为准：

- `leafEncodedLength(entries, interval)` 精确计算页头、压缩后记录和重启表的总大小；
- `chooseLeafSplit` 对每个候选点分别计算左右两页的独立编码大小；右页在分裂点重新开始压缩；
- 合并仅当两个逻辑连续区间拼接后，连同新重启表仍能放入一页时执行；
- 内部页分裂和合并同样按完整分隔键及子指针的编码大小计算。

如果单个键连一个叶页记录，或内部页中的一个分隔键加两个子指针都无法放入配置页大小，插入会在修改前抛出 `PageOverflowError`。

## 损坏页防护

解码会校验：

- magic、版本、类型、保留标志、精确页长和 CRC-32C；
- 重启点数量、表边界、首偏移为零、偏移严格递增；
- 每条记录头和记录体都位于其重启区间及页内；
- 所有长度字段不会导致越界读取；
- `shared_prefix_len <= 前一键长度`；
- 重启记录前缀长度必须为零；
- 前缀长度符合最长公共前缀的规范编码，且逻辑键严格递增。

这些检查在重建键之前完成，因此损坏的前缀长度不会触发越界读取。
